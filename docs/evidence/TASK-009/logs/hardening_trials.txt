== Trial 2. Theia's single-process mode (--no-cluster): can the RunAsNode fuse be switched off? ==
  Theia starts its backend as a child process through ELECTRON_RUN_AS_NODE, which needs the RunAsNode fuse. With
  --no-cluster it runs the backend inside the window's main process instead, and nothing needs that fuse. The
  question is what the processes the backend starts then inherit. In this trial a script stands in for the host
  program, which the backend starts in the same way; it records the descriptors it was started with and exits.
  In the delivered configuration, with the backend as a separate process, a process the backend starts inherits 5 descriptors:
      1  the event loop's eventfd
      2  the event loop's eventpoll
      1  the file <electron>/resources/default_app.asar
      1  the file <electron>/v8_context_snapshot.bin
  In single-process mode, a process the backend starts inherits 29 descriptors:
      4  Chromium shared memory
      4  a pipe
      4  a socket
      3  the event loop's eventfd
      4  the event loop's eventpoll
      2  the event loop's inotify
      1  the file <electron>/chrome_100_percent.pak
      1  the file <electron>/chrome_200_percent.pak
      1  the file <electron>/icudtl.dat
      1  the file <electron>/locales/en-US.pak
      1  the file <electron>/resources.pak
      1  the file <electron>/resources/default_app.asar
      1  the file <electron>/v8_context_snapshot.bin
      1  the graphics device /dev/dri/renderD128
  Result: rejected. In single-process mode a process started by the backend inherits descriptors of the window's
  main process: its sockets, Chromium's shared memory and the graphics device. The backend therefore stays a
  separate process, and the RunAsNode fuse stays on until the backend can start another way (docs/security, R-09,
  OSD-09). Even a separate backend passes on its event loop and two of Electron's files, which is why the host
  closes whatever it inherits before it opens anything (platform/desktop/lifecycle/application_lifecycle).
