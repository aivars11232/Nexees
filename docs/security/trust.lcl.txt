DATA:
    ID: data.sec_assumptions
    TYPE: LIST[STRING]
    VALUE: ["SEC-A01 | The device operating system is not compromised: no root or jailbreak and no kernel exploit. Every boundary here relies on OS process isolation, file permissions, the Android app sandbox and the OS credential store.", "SEC-A02 | The device owner controls the device lock. A device without a screen lock, or a shared OS account, gives a physical attacker the user's authority; step-up protects only the sensitive actions.", "SEC-A03 | Device clocks may differ. Expiry is enforced by the destination with its own clock, a bounded skew allowance and a destination-side maximum lifetime, so no security property depends on synchronized clocks.", "SEC-A04 | The cryptographic libraries in use (rustls with ring, the OS keystores, platform signature verification) are correct. Nexees adds no cryptography of its own.", "SEC-A05 | The LCL engine at the pinned commit evaluates deterministically and, called for parsing, validation and compilation, has no host effect (SA-05; tested by SG-07).", "SEC-A06 | Third-party services (providers, the auth backend, Open VSX, release hosting, the off-LAN route) are untrusted for authority and may be compromised; compromising one yields nothing beyond what was disclosed to it (SA-04, SA-06).", "SEC-A07 | The authenticated user is not the adversary of their own device. Nexees protects the user from untrusted content, peers and services, not from deliberate choices the user makes within the invariants.", "SEC-A08 | Code already running as the same OS user is outside the boundary Nexees can enforce (SA-01). Nexees keeps its own components from becoming that code's tools (SI-17, SI-28) and records the rest as R-01."]
    DESCRIPTION: "Security assumptions in addition to the architecture's SA-01 to SA-08, which still apply. An implication none of them covers is a blocker."
