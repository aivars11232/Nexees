SPECIFICATION:
    ID: specification.arch_flows
    NAME: "Device hosts and data and authority flows"
    VERSION: "0.5.0"
    KIND: kind.part.data
    DESCRIPTION: "The two device hosts, which own execution and storage on their own device, and the flows that move data and authority between subsystems and devices. The local, remote and sync paths are independent: local work needs neither of the other two, remote control moves requests but never execution, and sync moves content but never authority (A1, A9). Every shared-core subsystem except SS-HELP runs unchanged in both hosts; SS-HELP is passive library code the clients use directly."

DATA:
    ID: data.arch_host_desktop
    TYPE: OBJECT[REF(type.arch_host)]
    VALUE:
        host_id: "HOST-DESKTOP"
        device: "desktop"
        process_model: "A local host process separate from the window process, both running as the same non-elevated OS user. There is one host per OS user: a second start attaches to the running host instead of creating another. Windows attach over IF-ATTACH. With keep-running-after-close enabled, closing the last window leaves the host and its authorized background work running; with it disabled, the host pauses its sessions at a checkpoint and then stops. The IDE foundation's own backend services, wherever TASK-003 and TASK-009 place them, reach workspace files only through workspace scope and the revision service and gain no agent authority."
        runs: ["SS-LOCAL-HOST", "SS-DOMAIN-PROTOCOL", "SS-STATE", "SS-WORKSPACES", "SS-SECURITY", "SS-TOOLS", "SS-AGENT", "SS-CONTEXT", "SS-TASKING", "SS-PROVIDERS", "SS-LCL", "SS-ACCOUNTS", "SS-SETTINGS", "SS-REMOTE", "SS-SYNC", "SS-UPDATES", "SS-PLATFORM-DESKTOP"]
        attaches: "Desktop client windows over authenticated local IPC; paired peer hosts through the receiver, only while receiving is enabled."
        receiver: "Off on a fresh install. When enabled it runs inside the host and lives exactly as long as the host does. Start-at-user-login starts the host in the user's login session. Boot before login and operation after logout are reported as unsupported unless TASK-003 proves a user-level mechanism for them (RC-05)."
        independence: "Needs no other device. Remote control and sync with Android are optional additions to local work."

DATA:
    ID: data.arch_host_android
    TYPE: OBJECT[REF(type.arch_host)]
    VALUE:
        host_id: "HOST-ANDROID"
        device: "android"
        process_model: "The local host runs inside the Nexees Android app, in the app's process or in its own app service, under Android lifecycle rules. It persists every edit before showing it as saved and checkpoints at action boundaries, so process death loses no committed work and interrupted effects are reconciled on restart (A3, A4)."
        runs: ["SS-LOCAL-HOST", "SS-DOMAIN-PROTOCOL", "SS-STATE", "SS-WORKSPACES", "SS-SECURITY", "SS-TOOLS", "SS-AGENT", "SS-CONTEXT", "SS-TASKING", "SS-PROVIDERS", "SS-LCL", "SS-ACCOUNTS", "SS-SETTINGS", "SS-REMOTE", "SS-SYNC", "SS-UPDATES", "SS-PLATFORM-ANDROID"]
        attaches: "The Android client in the same app; paired peer hosts through the receiver, only while receiving is enabled."
        receiver: "Off on a fresh install. When enabled, availability uses the mechanisms the supported Android versions permit, such as a visible foreground-service notification with a stop control. Doze, process death, force-stop and revoked permissions make it unavailable, which is reported as such; permanent availability is never promised (RC-15)."
        independence: "Creates and edits local workspaces, validates LCL and runs the local agent with no PC and, apart from network models and first-time online signup, with no internet (A1, A2)."

DATA:
    ID: data.arch_flow_local_execution
    TYPE: OBJECT[REF(type.arch_flow)]
    VALUE:
        flow_id: "FL-LOCAL-EXECUTION"
        name: "Local agent execution"
        trigger: "A user, the scheduler or an adopted LCL task starts or continues work in a workspace whose session runs on this device."
        steps: ["SS-TASKING | Selects the task whose dependencies are closed and checks stop conditions and blockers.", "SS-AGENT | Loads the session binding of device, workspace, revisions and generation from the state store.", "SS-CONTEXT | Builds the model context from authoritative state, scoped files and the adopted LCL constraints.", "SS-PROVIDERS | Sends the request through the provider interface within the disclosure policy and the budget.", "SS-AGENT | Checks the proposed action against the session's generation and phase.", "SS-TOOLS | Dispatches the typed tool call, which SS-SECURITY authorizes and SS-STATE journals.", "SS-PLATFORM-DESKTOP, SS-PLATFORM-ANDROID | Executes it within workspace scope, the sandbox and resource bounds.", "SS-STATE | Records the structured result, its outcome and evidence tied to the input revisions.", "SS-TASKING | Verifies, then continues, stops or asks for approval; completion goes only through the verification and cleanup gates."]
        authority: "The execution host's permission engine and the user's explicit approvals. Models and content only propose."
        never: ["Use another device's host, a PC endpoint or a remote snapshot as the source of truth for local work (A2).", "Let UI focus, a model change or sync change the session's workspace, device or rules (R11, R22)."]

        authority: "This device's own policies."
        never: ["Block local work on PC connectivity or pairing (C19).", "Unlock secrets or grant remote authority because the network is absent (A2)."]

DATA:
    ID: data.arch_flow_remote_request
    TYPE: OBJECT[REF(type.arch_flow)]
    VALUE:
        flow_id: "FL-REMOTE-REQUEST"
        name: "Remote request, Android to Desktop or Desktop to Android"
        trigger: "A user on one device asks for a supported action on a paired device."
        steps: ["SS-DESKTOP-CLIENT, SS-ANDROID-CLIENT | The user chooses an explicit destination device, session, workspace or application and the typed operation.", "SS-REMOTE | On the sending host, builds the typed envelope with request ID, expected revisions, permission epoch and expiry, and records it as pending.", "SS-PLATFORM-DESKTOP, SS-PLATFORM-ANDROID | Carries it over the authenticated, encrypted channel.", "SS-REMOTE | On the destination, admits it only if receiving is enabled, the sender is paired and not revoked, the direction has a grant, and the target, epoch and expiry are valid and the request ID is unseen.", "SS-SECURITY | On the destination, rechecks capabilities, scope, policy, lock state and freshness immediately before execution, and asks the local user when policy requires it.", "SS-TOOLS, SS-AGENT | On the destination, executes through the same tool dispatch or session control that local work uses.", "SS-REMOTE | On the destination, records the outcome by request ID and acknowledges it; SS-SECURITY audits it.", "SS-REMOTE | On the sending host, reconciles the pending record; without an acknowledgment the outcome stays unknown."]
        authority: "The destination host alone (RC-01, RC-10)."
        never: ["Treat a natural-language request, a shared account, pairing or sync as permission (RC-01, RC-03).", "Move execution, transfer a task or change either device's foreground workspace (RC-20).", "Fall back to an ambient or foreground workspace when the target is missing (RC-09).", "Report success without the destination's acknowledged outcome (RC-12)."]

    TYPE: OBJECT[REF(type.arch_flow)]
    VALUE:
        flow_id: "FL-SYNC"
        name: "Content synchronization"
        trigger: "Content of a workspace the user selected for sync changes on one replica, or a paired peer reconnects."
        steps: ["SS-WORKSPACES | Records the change as a new revision.", "SS-SYNC | Adds it durably to the outbox with its base revision and hash.", "SS-PLATFORM-DESKTOP, SS-PLATFORM-ANDROID | Carries it to the peer when the peer is reachable.", "SS-SYNC | On the peer, validates path, size, schema, revision and peer authority.", "SS-SYNC | On the peer, applies it transactionally through SS-WORKSPACES, or records a conflict that keeps both versions."]
        authority: "Each replica's own validation. Sync carries content, never authority."
        never: ["Carry commands, approvals, grants, secrets or device keys (C22).", "Adopt synced LCL text into a running session, or change an execution owner (A7).", "Overwrite unsaved buffers, or resurrect or silently delete newer work (A6)."]

    VALUE:
        flow_id: "FL-IMPORT"
        name: "LCL file and ZIP import"
        trigger: "The user imports LCL files or a ZIP archive into a chosen workspace on a device."
        steps: ["SS-DESKTOP-CLIENT, SS-ANDROID-CLIENT | The platform picker selects the sources and the user chooses an existing destination workspace or a new one.", "SS-LCL | Captures the import transaction: target device, workspace, root mapping, permissions and base revision.", "SS-LCL | Streams the entries into app-private staging within the resource bounds and path checks.", "SS-LCL | Plans the structure from the roles the LCL core establishes; any ambiguity becomes a decision for the user.", "SS-DESKTOP-CLIENT, SS-ANDROID-CLIENT | Shows the preview; the user confirms or cancels.", "SS-LCL | Rechecks the destination revision and publishes atomically through SS-WORKSPACES and SS-STATE.", "SS-LCL | Records the result as a draft revision; validation and adoption are separate steps (FL-ADOPTION)."]

    VALUE:
        flow_id: "FL-ADOPTION"
        name: "LCL revision adoption"

        never: ["Apply edited, synced or imported rules to a running session without validation and adoption (C22).", "Let LCL rules weaken Nexees security (authority_hierarchy)."]
