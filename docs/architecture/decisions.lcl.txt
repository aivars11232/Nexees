DATA:
    ID: data.arch_ad_01
    TYPE: OBJECT[REF(type.arch_decision)]
    VALUE:
        decision_id: "AD-01"
        title: "A portable shared core in a local host on each device, with thin clients"
        status: "accepted"
        task: "TASK-002"
        date: "2026-10-03"
        problem: "Desktop and Android must share one meaning of workspace, agent, task, LCL and security state (C15), and Android must work as a standalone host with no PC (C19, A1, A2)."
        options: "(a) One PC-hosted server with thin clients. (b) Separate Desktop and Android implementations. (c) One portable core running in a local host on each device, with platform adapters and thin UI clients."
        decision: "(c). core/ holds the domain, security, state, agent, tool, LCL, sync and remote logic and runs unchanged in both hosts; platform/ implements the core's ports for each operating system; apps/ composes the host and presents its state."
        why: "(a) fails standalone Android (A1, A2), and (b) duplicates domain logic (no_unnecessary_code). (c) is the shape system_architecture v0.2 describes."
        security_impact: "One permission engine, one audit implementation and one set of invariants to test on both devices."
        reuse_impact: "The core needs a language, runtime and libraries that run on Android as well as on Desktop: open decision PD-CORE-RUNTIME for TASK-003."
        reversal: "If TASK-003 cannot prove a portable core, this decision is reopened before TASK-005 fixes the scaffold. Android is never demoted to a remote-only client instead (A8)."
        verification: "check_architecture.py checks that every core/ slot belongs to a shared_core subsystem and that both hosts compose the same core; TASK-003 must prove the Android hosting path."

DATA:
    ID: data.arch_ad_02
    TYPE: OBJECT[REF(type.arch_decision)]
    VALUE:
        decision_id: "AD-02"
        title: "The Desktop host is separate from the window, one per OS user"
        status: "accepted"
        task: "TASK-002"
        date: "2026-10-03"
        problem: "The receiver and authorized background work must survive closing the window, and reopening the window must not start a second executor (RC-04, RC-T14)."
        options: "(a) Everything in the window process. (b) A separate privileged system service. (c) A separate host process at user privilege that windows attach to."
        decision: "(c). apps/desktop/src/application_host is the host's composition root, a single instance per OS user; windows attach to it over authenticated local IPC (IF-ATTACH)."
        why: "(a) dies with the window, and (b) violates RC-05 and RC-23. (c) satisfies RC-04 at user privilege."
        security_impact: "It adds a local IPC boundary, which must authenticate the peer process by OS identity, admit only the same user and bound its messages (RC-23)."
        reuse_impact: "The IPC mechanism and the IDE foundation's backend placement are open decisions PD-LOCAL-IPC and PD-IDE-PLACEMENT; the layout has no slot for the IPC channel yet (GAP-01)."
        reversal: "If the approved renderer or foundation rules out a separate process, the host role moves to whichever process outlives the window; the receiver still may not depend on the window."
        verification: "RC-T02 and RC-T14, at TASK-009, TASK-056 and TASK-070."

DATA:
    ID: data.arch_ad_03
    TYPE: OBJECT[REF(type.arch_decision)]
    VALUE:
        decision_id: "AD-03"
        title: "One effect path under one permission engine"
        status: "accepted"
        task: "TASK-002"
        date: "2026-10-03"
        problem: "Agents, remote requests and UI-initiated agent actions all cause effects; separate paths would duplicate authorization and invite bypasses (C9, C10, RC-25)."
        options: "(a) A dispatcher for each kind of caller. (b) One tool dispatch under one permission engine, with each caller as an adapter."
        decision: "(b). core/tools/tool_dispatch is the only route to an effect and core/security/permission_engine the only authorization point; core/remote/command_dispatch only admits remote envelopes and hands them over."
        why: "One place enforces scope, journaling, audit and the read-only orientation (H3)."
        security_impact: "There is no privileged bypass path (RC-23), and every effect is journaled and audited."
        reuse_impact: "None."
        reversal: "A new kind of caller is added as an adapter; a second dispatcher would need an explicit architecture change with a security review."
        verification: "tests/unit/tool_dispatch and RC-T05; check_architecture.py checks the single-path list against the catalogue."

DATA:
    ID: data.arch_ad_04
    TYPE: OBJECT[REF(type.arch_decision)]
    VALUE:
        decision_id: "AD-04"
        title: "Authority is decided on the executing host"
        status: "accepted"
        task: "TASK-002"
        date: "2026-10-03"
        problem: "Two-way remote control needs per-direction trust that neither a sender, a shared account nor synchronization can manufacture (RC-01, RC-03, C30)."
        options: "(a) The sender authorizes. (b) Grants are synchronized between devices. (c) The destination decides, using grants it holds itself."
        decision: "(c). Grants and approvals are device-local records of SS-SECURITY, keyed by peer, direction and capability (ST-AUTHORITY) and never synced; the destination rechecks everything immediately before execution."
        why: "Both (a) and (b) let one device, or a copied file, grant authority on another."
        security_impact: "Revocation is local and immediate, and a compromised sender cannot widen its own grant."
        reuse_impact: "None."
        reversal: "None foreseen: this follows directly from RC-10."
        verification: "RC-T01, RC-T05 and RC-T08; verify.arch_authority_never_synced."

DATA:
    ID: data.arch_ad_05
    TYPE: OBJECT[REF(type.arch_decision)]
    VALUE:
        decision_id: "AD-05"
        title: "Control and content travel separately over one secure channel per platform"
        status: "accepted"
        task: "TASK-002"
        date: "2026-10-03"
        problem: "Commands and approvals must never be replayed like offline content, yet both need an authenticated peer channel (C22, RC-17, RC-19)."
        options: "(a) One message stream for everything. (b) Separate transports. (c) One secure channel per platform carrying two separate message families."
        decision: "(c). IF-REMOTE and IF-SYNC are separate message families over IF-TRANSPORT, sharing pairing and revocation."
        why: "(a) lets commands ride a sync queue, and (b) duplicates transport and pairing (RC-25)."
        security_impact: "Expired control messages are never queued as content, and there is one channel to audit and harden."
        reuse_impact: "The channel library and the off-LAN route are open decision PD-TRANSPORT."
        reversal: "If the selected library changes, only the transport adapters change."
        verification: "RC-T10 and RC-T15; tests/integration/sync/two_way_sync."

    VALUE:
        decision_id: "AD-12"
        title: "Subsystem dependencies are acyclic and follow the build order"
        status: "accepted"
        task: "TASK-002"
        date: "2026-10-03"
        problem: "The permission engine (TASK-022) is built before settings (TASK-030) and accounts (TASK-027), and the agent loop (TASK-034) before the scheduler (TASK-053), yet each pair interacts."
        options: "(a) Mutual dependencies. (b) Dependency inversion: the earlier subsystem defines a port or emits an event, and the later one implements or consumes it."
        decision: "(b). SS-SECURITY defines the policy input and the step-up port that SS-SETTINGS and SS-ACCOUNTS supply; SS-AGENT reports completion proposals that SS-TASKING evaluates; SS-SECURITY reads binding records from the store instead of calling SS-WORKSPACES."
        why: "Each task can then build and test its subsystem against finished dependencies only."
        security_impact: "The permission engine never trusts a caller's claim of scope; it reads the authoritative binding records."
        reuse_impact: "None."
        reversal: "A task that needs a reverse dependency changes this architecture explicitly."
        verification: "check_architecture.py checks that the dependency graph is acyclic and that every interface consumer depends on one of its providers."
